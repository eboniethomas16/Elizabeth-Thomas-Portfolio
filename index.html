SMS Spam Detection

HAM vs SPAM: SMS Spam Detection - Machine Learning Project

A machine learning project that classifies SMS messages as legitimate (ham) or spam, with a focus on keeping false positives low so real messages are not lost. Using the SMS Spam Collection (5,572 labelled messages), I engineered content-based features, searched hundreds of thousands of feature combinations, and benchmarked seven classifiers before and after refinement.

Technical Achievements

  • Cut false positives by 67%. Reduced legitimate messages wrongly flagged as spam from 127 to 42 on the held-out test set while also improving recall.
  • Engineered 19 candidate features from raw text, including regex-based detectors for URLs, currency symbols, phone numbers and short codes, plus length-normalised ratios that stop long messages being flagged simply for being long.
  • Built a multithreaded feature-subset search that evaluates all unique combinations of 19 features (524,287 subsets) with Multinomial Naive Bayes. It runs in memory-safe batches and ranks results by fewest false positives subject to a minimum recall constraint, so a “predict everything as ham” model cannot win.
  • Prevented data leakage. Oversampled only after splitting, kept the validation set at its natural ham/spam ratio so false-positive counts stayed realistic, and used the test set once for the final evaluation.
  • Benchmarked seven classifiers before and after feature refinement, reporting per-model deltas and translating precision gains into false-positive counts that are easy to interpret.
  • Diagnosed model behaviour. Explained why Gaussian Naive Bayes improved most (correlated features had violated its independence assumption) and why the single Decision Tree regressed while the Random Forest on the same features improved.
